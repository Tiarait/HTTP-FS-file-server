# Conventions

## Source of truth

- App version and SDK levels: `app/build.gradle`
- Behavior: application and web client code
- Public wording: this `docs_ai/` tree only

## Docs hygiene (public tree)

- Keep **`docs_ai/` self-contained**: links stay inside this folder; do not require or deep-link to other repo paths for published docs.
- Prefer product behavior and public integration surfaces over long code walkthroughs.
- Do **not** commit or paste real signing passwords, private keys, ACME account material, or AdMob unit IDs.
- Avoid step-by-step attack or bypass recipes.

## Code

- Free/Pro gates: Pro façade (`UtilsPro` / `ExtendUtils`) — avoid duplicating business logic in flavor source sets.
- Match existing style (AppCompat settings UI, existing storage helpers).
- Web UI: build from `client/` then deploy assets; runtime `config.js` is generated by the server.
- Network advertise/bind behavior: keep Home, Settings Address, and server lifecycle consistent — see [../features/network-address.md](../features/network-address.md).

## For AI / support answers

When answering end-user setup questions from this tree, prefer `user/ui-map.md` → `user/recipes.md` → FAQ before deep feature docs.

## Signing

Local `gradle.properties.local` (or equivalent) stays on the signing machine — never in the public docs tree. See [../getting-started/build.md](../getting-started/build.md).
